## Контраст постоянных цветов

Расчёт по относительной яркости sRGB, без округления результата для решения о прохождении порога.

| Пара | Контраст |
| --- | ---: |
| Основной тёмный текст `#2A2019` / кремовый `#FBF7F2` | 14,93:1 |
| Второстепенный текст `#6B5C4E` / кремовый | 6,03:1 |
| Второстепенный текст / песочный `#EFE3D3` | 5,08:1 |
| Белый / петроль `#315B68` | 7,43:1 |

Эти постоянные сочетания проходят AA для обычного текста. Это не означает, что автоматически проверен каждый пиксель текста поверх всех фотографий.

## Сохранённое замечание

**Плавная смена тёмного текста на белый в петрольной зоне.** Конечные цвета выбираются с учётом контраста, но CSS-переход длительностью 0,72 с проходит через промежуточный серый. Например, на фоне около `rgb(89, 122, 132)` средний серый может дать примерно 1,15:1. Это расчёт промежуточного состояния, а не измерение каждого кадра браузера.

Владелец выбрал сохранить текущую плавность текста. Анимация не изменена. Строгое соответствие WCAG по контрасту для этого перехода не заявляется. Вариант дальнейшего исправления: сохранить плавный фон и переключать текст между контрастными цветами без промежуточного серого.

## Предложения на следующий проход

1. **Уточнить предложение перманентного макияжа.** Оно упомянуто на первом экране и у мастера, но отдельной карточки услуги с ценой нет. Сначала подтвердить актуальную услугу, стоимость и продолжительность.
2. **Передавать выбор калькулятора в запись**, когда будут подтверждены поддерживаемые параметры или API DIKIDI. Сейчас пользователю честно объяснён повторный выбор; идентификаторы услуг не подставлялись наугад.
3. **Проверить реальный путь записи на iPhone с VoiceOver.** В этой среде доступен Chromium; проверка на физическом Safari и чтение настоящим экранным диктором не выполнялись.

## Границы проверки и публикация

- Проверялись адаптивные состояния при заданной ширине 320, 390 и 1440 px, навигация, галереи, калькулятор и диалог фото. Полоса прокрутки уменьшает доступную ширину документа, что также учтено при осмотре узкого экрана.
- Проверки Node для запуска калькулятора: четыре сценария (root/Astro × современный/старый API media query), по 96 сочетаний цен в каждом, восстановление формы и жизненный цикл анимации.
- Astro проверен и собран из локального снимка контента. Компоненты, общий CSS, JS и снимок контента обновлены согласованно. База Directus не изменялась; при переходе на сборку из действующей CMS нужно перенести в неё новые тексты отзывов.
- Настоящие записи, сообщения WhatsApp и звонки не отправлялись. Внешний сервис записи целиком не тестировался.
- Это ограниченный UX-аудит с исправлениями, а не сертификат полного соответствия WCAG.
- Изменения находятся локально. Публикация на GitHub Pages требует коммита и отправки в `master`.
