## Исходники и сборка

- `app/src/data/service-pages.ts` — описания, вопросы и привязки фотографий/мастеров.
- `photoFallbacks` в описании страницы — локальные фотографии с размерами и alt-текстами. При наличии строки портфолио с тем же `image_path` используются данные CMS; до её добавления работают локальные фотографии.
- `app/src/components/ServiceDetail.astro` — общий шаблон пяти страниц.
- `app/src/data/site-content.json` — локальный снимок цен, акции, графика и публичного контента.
- `service-pages.css` — оформление страниц; общие кнопки, цвета и шрифты берутся из styles.css.
- `scripts/export-service-pages.mjs` — переносит пять готовых страниц из Astro в корневые каталоги; синхронизирует блоки услуг и калькулятора, SEO-поля и данные салона в head главной, а также sitemap. Остальная разметка главной сохраняется.

Для обновления из локального снимка в Git Bash из корня проекта:

```bash
CONTENT_SOURCE=snapshot PUBLIC_ENABLE_ANALYTICS=true npm run build --prefix app
node scripts/export-service-pages.mjs
node tests/service-pages.cjs
node tests/service-prices.mjs
node tests/startup.cjs
```

HTML в пяти корневых каталогах сгенерирован: править его вручную не нужно, изменения перезапишутся при экспорте. Для публикации текущий хостинг менять не требуется — готовые HTML и CSS работают на GitHub Pages. Исходники Astro сохранены в репозитории вместе с готовыми страницами, чтобы их можно было пересобрать на другом компьютере.

GitHub Pages публикует ветку `master`, корневую папку. Настройка `_config.yml` исключает `app/`, локальную CMS, скрипты, тесты и Markdown-заметки из обработки и публикации. Это необходимо: без исключения `app/` Jekyll принимает блоки TypeScript между `---` в файлах Astro за YAML и останавливает сборку с `Invalid YAML front matter`. Готовые страницы в корневых каталогах и их ресурсы остаются в публикации. Пустой файл `.nojekyll` добавлять вместе с этой настройкой не нужно: он отключит и применение этих исключений.

Существующая база Directus не менялась. При будущей сборке из CMS вместо снимка нужно внести туда подтверждённые цену, скидку и график. Сборка по умолчанию использует CMS; команды выше явно выбирают снимок.

## SEO и проверка

На новых страницах добавлены JSON-LD `BeautySalon`, `Service` с начальной ценой и `BreadcrumbList`. На главной — данные `BeautySalon`. Рейтинг, вымышленные отзывы и неподтверждённые координаты не добавлены. Разметка описывает видимое содержимое; она не гарантирует позицию в поиске или расширенный результат. См. [документацию Google](https://developers.google.com/search/docs/appearance/structured-data/local-business).

После публикации:

1. Проверить пять адресов по HTTPS и обновлённый sitemap.xml.
2. Проверить опубликованные страницы в Rich Results Test и Search Console. Локальная проверка JSON-LD не заменяет внешний валидатор.
3. Отправить новые страницы на индексирование; обновить sitemap в Google Search Console и Яндекс Вебмастере.
4. Согласовать 10% скидку и график до 21:00 в DIKIDI и карточках организации. Внешние сервисы этой правкой не изменялись.
5. При замене фотографий ламинирования обновлять файлы и их привязки/размеры в `app/src/data/service-pages.ts`, затем пересобрать и экспортировать страницы.

Новые страницы написаны под разные услуги и связаны между собой, без создания одинаковых страниц под районы или повторения ключевых слов. [Рекомендации Google по структуре и содержанию сайта](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=ru).
